## Prioritized findings and smallest replacement proofs

1. **P0 · Remove the unused `git-format-staged` dependency. Keep the existing transaction.** The manifest pins `"git-format-staged": "4.0.2"`, while the hook runs `exec python3 tools/style/run.py --staged`. The driver evaluates formatting plus cross-file lint against one staged snapshot, then compares and publishes a candidate index under the Git lock. In a disposable repo the installed upstream tool with `--no-update-working-tree` exited `1` when the formatter exited `7` on `z.txt`. At that point `git show :a.txt` had already changed from `'staged  \n'` to `'staged\n'`, `:z.txt` retained `'staged  \n'`, and the working copy of `a.txt` retained `b'unsaved worktree witness  \n'`. This demonstrates a gap in direct substitution. Lefthook's `stage_fixed` calls `git add`, and pre-commit temporarily stashes unstaged edits. Their stock workflows would need an isolated acceptance test before taking ownership of the index. The existing shell hook is three lines. **Proof:** remove the dependency in a candidate, run the normal locked style provisioning and `tools/style/test_hook.py`, then use an ordinary commit after clean build. Require the overlap, late lint/error, competing writer, alternate index, and linked-worktree cases to pass before adopting any alternate hook.
